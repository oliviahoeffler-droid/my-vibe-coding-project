# Validation Brief

> Module 2 · Validation. Frame the riskiest assumption, then build to test it. **This locks your scenario, no switching after M2.**

## Scenario

FirstCall (own product)

## Riskiest assumption

_The one belief that, if false, sinks the idea._

The riskiest thing I am assuming is that there is a need for speed to call in the marketplace, and contractors are ok if AI does this on their behalf.

## Hypothesis

> We believe **providing a fast, AI-driven scheduling assistant for online-lead submissions** will cause **more lead conversions** for **B2B Home Service Contractors**. We'll know we're right when **lead appointments increase by 40%, lead conversions (sales) increase by 25%.**.

## Risk type

- [x] Value (do they want it?)
- [ ] Usability (can they use it?)
- [ ] Feasibility (can we build it?)
- [ ] Viability (should we?)

## Kill switch

_The result that would make you stop or pivot._

If the prototype does not generate excitement for filling a need, then we pivot.

## The three ingredients

- **Real data (domain metrics):** _____
- **User voice (verbatim quotes):** _____
- **Hypothesis (above):** ✓
